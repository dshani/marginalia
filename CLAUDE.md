# Marginalia

PDF reader for writing spaced-repetition prompts in the margins (Andy Matuschak's workflow). The app lives in `marginalia/`: plain HTML/CSS/JS, classic scripts on `window.Marginalia`, no build step, no npm. `desktop/` wraps it as the Mac app `Marginalia.app` (Electron; npm is used only there), which keeps the library outside any browser (D22). The project is made for a public repository (D32): see "Publishing".

"The user" in this file is the person on whose computer you work. `CLAUDE.local.md`, when it exists, holds the notes of that one computer (its folders, what is installed, what was verified there). It is not in the repository.

## Before changing behaviour
- **Decisions**: `marginalia/docs/DECISIONS.md` (D1–D33) records what the project's first author settled. Treat it as fixed; ask the user before changing any of it.
- **Contracts**: `marginalia/docs/SPEC.md` §17 (module signatures, bus events) and `marginalia/docs/BUILD-NOTES.md` (binding overrides; it wins over SPEC). Read the sections for the modules you touch; for the Mac app, "Desktop app (binding)".
- **Usage**: `marginalia/README.md`; building and testing the Mac app: `desktop/README.md`; for a new reader: `README.md` at the top.

## Conventions
- One module per `js/<name>.js`, wrapped as in SPEC §17.1. Pure modules (util, scheduler, prompts, similar, context, keys, layout, anchors, markup, exporter, undo) load in Node with no DOM.
- Each UI module owns its DOM host and its `css/<name>.css`; modules talk through the §17 functions and `M.bus` events.
- A change that a person makes to a card is a step of `M.undo` (D33): the view saves a copy of the record with `M.cache.savePrompt(copy, {content: true, step: true})`, or deletes and restores with `{step: true}`. A write that is not the person's own change (a review answer, a send record, a found position, an import) carries no `step`. Contract: BUILD-NOTES "Undo and redo".
- User text reaches the DOM only through `M.util.escapeHtml` or `M.markup.render`. Dialogs and notices use `M.app.confirm` and `M.app.toast`.
- The Anthropic API key stays in this browser's localStorage; exports, logs and toasts never carry it.
- PDF.js stays at 3.11.174 with `isEvalSupported: false`; every cdnjs tag keeps its SRI hash.

## Run and check
- `bin/marginalia` is the command (the user may have linked it as `marginalia` into a folder on the PATH). Once the Mac app is installed (`/Applications/Marginalia.app`), `marginalia`, start, stop, restart and status open, quit and show the app; without it they serve the app at http://127.0.0.1:8765/ with `marginalia/tools/serve.py` and open Chrome, or Brave when Chrome is missing. `marginalia app` builds, self-tests and installs the app. `marginalia help` lists start, stop, restart, status, test, build and app. Keep that address fixed: a browser keeps a separate library for every address, and Obsidian's "Open in Marginalia" links use it.
- A running server keeps the code it started with. The Mac app runs its own copy of the web app and of `serve.py`, which changes only when the user runs `marginalia app` (after quitting the app): leave that step to the user. Without the app, after changing `serve.py`, restart the user's server with `marginalia stop && marginalia start` (`restart` also opens a browser window).
- `marginalia test` runs everything: `node --test` (no directory argument; Node 23 rejects `node --test test/`), `tools/xref.py`, `tools/xref-rt.js`, the headless boot `tools/smoke.js`, the Python tests (`test/test_serve.py`, `test/test_command.py`), then `node --test` in `desktop/`.
- Browser pane: start your own test server from Bash in the background, `python3 -I -B marginalia/tools/serve.py --port 8791 --dir <absolute app path> --obsidian-sandbox <your scratchpad>/obsidian-sandbox --backup-dir <your scratchpad>/backups`, then call `preview_start` with the name `marginalia-test` (or the url http://127.0.0.1:8791). The two entries in `.claude/launch.json` only attach to a running server. Keep it that way: when the app starts a server itself, it runs outside Claude's own permissions, and macOS then asks the user whether Python may read the Documents folder. The user's server on 8765 (entry `marginalia`) is for looking only; once the Mac app runs it, a browser page there shows the cover "Marginalia is now an app" and follows a `marginalia://` link on a `#reader/…` hash, so leave that page alone. `serve.py` sends `Cache-Control: no-cache`, so a reload picks up edited files. To test the cover, give your own test server `--app <x.y.z>` and load its page only on `/` or `#library`: on a `#reader/…` hash the cover follows a `marginalia://` link by itself during boot, before any `M.desktop._setOpener` stub can be set (and a hashchange to `#reader/…` after boot only rewrites the link). The reader forward is checked only in the Node tests (`test/desktop-dom.test.js`), which set the stub before boot.

## Desktop app
- The app shows its own copy of the web app and starts its own `serve.py` with `--app <version>`; that server refuses every POST without `X-Marginalia-Client: app` (409 "app_only"), and a browser page served by it shows the cover. Contract: BUILD-NOTES "Desktop app (binding)", part 1 and "Part 2".
- Windows (D31): the app has up to 8 windows, each a page of the web app (`/?w=<id>` for all but the first) with its own tabs. One page writes to the library at a time, the one that is used; the pages hand that role to each other (`M.store` in handover mode: the Web Lock "marginalia.writer"; `M.app.takeRole()`). A browser page keeps "One writing tab per origin". Contract: BUILD-NOTES "Windows"; tests: `marginalia/test/d31.test.js`.
- `npm run app` in `desktop/` builds the app and runs its packaged self-test; `node --test` in `desktop/` never loads Electron (`test/main.test.js` mocks it); its `test/docs.test.js` checks that this file, BUILD-NOTES and the READMEs keep the app's safety rules and promises, so keep those facts when you reword them. The build pins every CDN file in `desktop/vendor-lock.json`: commit the lock when a build adds a file, and change it by hand only to delete a line on purpose. It reads the signing certificate's name from `desktop/sign-identity`, which only the user creates.
- Tests and agents leave the user's app alone: never touch its data folder `~/Library/Application Support/Marginalia`, never install into `/Applications` or `~/Applications`, never launch the installed app, and never open a `marginalia://` link through macOS (the Node page tests stub `M.desktop._setOpener(fn)` before boot, as they stub `M.obsidian._setOpener`; a browser page cannot, see the test-server rule above).
- Never run the project's own `bin/marginalia` (or the `marginalia` link) for open, start, stop, restart or app to try it out. Whatever `MARGINALIA_APP` says, it works on port 8765, the user's server: stop and restart stop that server; open and start either open a browser page on it or, with a Marginalia app at `MARGINALIA_APP`, stop it and run `open -a`; and app builds in the project's `desktop/` (leave that to the user). Its only such use is restarting the user's server while no app is installed ("Run and check"). To try the command, do what `test/test_command.py` does: run a copy of `bin/marginalia` in a temp root in your scratchpad with its own `marginalia/` and `desktop/` (its server check then never matches the user's server), with `MARGINALIA_APP` an app path in that scratchpad, `MARGINALIA_PORT` and `MARGINALIA_APP_PORT` free ports (never 8765, 8791 or 8792; `MARGINALIA_APP_PORT` stands for the app's port 8765, which the tests never look at), `HOME`, `TMPDIR` and `MARGINALIA_BACKUP_DIR` in your scratchpad, and stand-ins for open, osascript, lsregister, npm and pgrep first on PATH.
- Every Electron or app launch uses `--self-test` with `--user-data-dir`, `--obsidian-sandbox` and `--backup-dir` in your scratchpad and a free port (never 8765); afterwards the copy is unregistered (`lsregister -u <app>`; the self-test runner does it) and `lsregister -dump` no longer names it.

## Obsidian
- The connection is an option (D32): Settings › Obsidian › "Connect Marginalia to Obsidian" (`settings.obsidian`, read through `M.obsidian.enabled()`). A new library has it off; a library that already sent a card keeps it on. While it is off the pages show no Obsidian command and ask the server nothing. A test that sends switches it on first (`M.settings.set("obsidian", true)`, or a stub with `enabled: () => true`). Contract: BUILD-NOTES "Obsidian", "The switch".
- "Note → Obsidian" (key O, and "Send to Obsidian" in the card and list menus) writes one note per book into the vault that the user chose, a real Obsidian vault on this computer, through `serve.py` (`GET /api/obsidian/vaults`, `POST /api/obsidian/note`). "Send all to Obsidian" in a book's or deck's ⋯ menu sends a whole book in one request (`POST /api/obsidian/notes`); it never adds a card twice. Without that API (the claude.ai artifact, `file://`) it opens `obsidian://` links. The contract is the "Obsidian (binding)" section of `marginalia/docs/BUILD-NOTES.md`.
- Testing never touches a real vault (any vault that Obsidian's own list names): do not write to it or read its notes. Every server you start gets `--obsidian-sandbox` or `--obsidian-config` with a throwaway vault, never Obsidian's own config. Never send a note from the 8765 server.
- In Obsidian's Live Preview a block shows its two comment lines. A user can hide them with a CSS snippet of their own that finds them by the block's shape: the comment line directly above the `###` heading, and the one directly below the line with the **Open in Marginalia** link. When `blockFor` (`js/obsidian.js`) changes that shape, tell the user that such a snippet must change too. Test a snippet in a second Obsidian with its own profile: `open -n -g -a Obsidian --args --user-data-dir=<scratchpad dir> --remote-debugging-port=<free port>`, where `<scratchpad dir>/obsidian.json` names a throwaway vault with `"open": true`.

## Backups
- The app's server (without the app, the `marginalia` server) saves a JSON backup of the library once a day into `~/Documents/Marginalia Backups` and keeps the newest 30 (`GET`/`POST /api/backup`, `GET /api/backup/latest`; client `js/backup.js`; contract: BUILD-NOTES "Automatic backup (binding)"). Time Machine, where it is on, copies that folder.
- Each backup also saves every book's PDF once into the folder's `PDFs` subfolder (`GET /api/backup/pdfs`, `POST /api/backup/pdf`, `GET /api/backup/pdf/<sha256>`). After an import, the page restores missing PDFs from there by itself.
- Library folders (L1) live in one meta record and travel in the JSON backup; contract: BUILD-NOTES "Library folders (binding)".
- Never write into the real backup folder. Every server you start gets `--backup-dir <your scratchpad>/backups` (or `MARGINALIA_BACKUP_DIR`). A test page's backup there could become "today's" file and make the user's own backup skip that day.
- Never open an `obsidian://` link: the real Obsidian would write into the real vault. After every page load, stub the opener first with `M.obsidian._setOpener(fn)`.

## Artifact
- `marginalia build` (or `python3 -I tools/bundle.py --artifact`) writes `dist/marginalia-artifact.html`, a page fragment for claude.ai. Its code comments stay free of the literal tags `<html`, `<head`, `<body`, `<!doctype` (the bundle must read as a fragment).
- No copy is published on claude.ai (D24; `marginalia web`, which opened one, is gone). Do not publish the artifact or spend work on it unless the user asks; keep the bundle's fragment rule above so `marginalia build` still works.

## Publishing
- The project is made for a public GitHub repository (D32): the licence is MIT (`LICENSE`), and `THIRD-PARTY-NOTICES.md` names the code of other projects. The user makes the repository and pushes. Do not make it, push to it or change who can see it without the user's word.
- No file holds private data of a person (a real name of the author, an e-mail address, a home folder), and no file holds text copied from a book or an article (the sample PDF's text was written for it). The licence carries the public name that the first author chose. Write `~/Documents/…` for a home folder, use made-up names in tests, and put what belongs to one person's Mac into `CLAUDE.local.md`. `desktop/test/docs.test.js` reads every file of the project for home paths and e-mail addresses.
- `.gitignore` leaves out what a build makes (`marginalia/dist/`, `marginalia/tools/.cache/`; `desktop/.gitignore`: `node_modules`, `.cache`, `build`, `out`) and the files of one Mac (`desktop/sign-identity`, `.claude/settings.local.json`, `CLAUDE.local.md`).
- `README.md` at the top is for a new reader: what Marginalia is, what it needs, how to install it, its limits. Keep it true when the install steps, the requirements or the limits change.

## Open gaps
- Not yet verified: Safari, live LaTeX transcription, folder drag and drop in a real browser.
- Tabs (D30) in the real Mac app: the packaged self-test runs the tab commands in the page, not the key presses. Not yet verified: Cmd+T, Cmd+W and Shift+Cmd+T as macOS gives them to the Window menu, Ctrl+Tab, Cmd+Shift+] and Cmd+1 to Cmd+9 reaching the page, a held Cmd+T or Cmd+W acting once, and Cmd+W closing the About panel.
- Undo and redo (D33) in the real Mac app: the tests press the keys in a page and in the fake window, and the packaged self-test runs a step, its undo and its redo through the page's own modules. Not yet verified: Cmd+Z and Shift+Cmd+Z reaching the page of the installed app when no text field has the focus (the Edit menu has the same keys for text; a click on Edit › Undo changes no card).
- Windows (D31) in the real Mac app: the packaged self-test hands the writer role between two real windows and moves a tab out through the page's own command. Not yet verified: the drag gestures with the pointer (a tab dragged out of its window, onto another window's strip, along its strip), the small picture that follows the pointer as macOS draws it, how long the window takes for a tab let go on the desktop (macOS moves the picture back first; on a Marginalia window it comes at once), Cmd+N as macOS gives it to the Window menu, where the pointer is reported when a drag ends outside the window, and a hand-over to a window that macOS has put to sleep for long.
- Obsidian link mode is not verified against the real Obsidian app (`obsidian://new` with `append` and `silent`); this includes "Send all" in link mode.
- The Mac app on a real Mac: installing it with `marginalia app`, opening it, moving a library over from a browser and updating it worked on the first author's Mac. Not yet verified: the visible window (closing hides it, Window › Marginalia, the Dock icon, Cmd+Q while hidden), the AppleScript quit of `marginalia stop` and its Automation prompt, `marginalia://` links delivered by macOS and a browser handing them over from the cover, and signing with a self-made certificate (whether the Documents permission then survives an update).
- For other people (D32): the Obsidian switch and the welcome card are checked by the tests, in a real browser page and by the packaged self-test. The files as git publishes them were cloned, tested and built once, on the first author's Mac. Not yet verified: a build on another Mac, an Intel Mac (the build refuses it), Apple's own Python 3.9 (the server is tested with Python 3.13 and 3.14), and the browser version on Linux or Windows.
